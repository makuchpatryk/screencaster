# Security hardening — Implementation Plan

## Summary

Fixes the 2 High and 8 Medium findings of the whole-repo security audit (`/screencaster-security`, 2026-11-05): a Go toolchain with 12 reachable stdlib advisories (H1), unchecked Playwright driver and Chromium downloads run as root by `setup` and the image build (H2), Chromium without its sandbox (M1), symlink escapes in `setup` extraction (M2) and in the working-directory path checks (M3), clear-text cookies kept forever in `jobs.db` (M4), an ungated release (M5), mutable action and image references (M6), releases without checksums (M7) and a root-by-default image (M8).

Base: `main` at `a0d88d3` (clean tree). The audit ran on `0abf352`; every line number below was re-read at `a0d88d3`. The unmerged `feature/cards-off-by-default` worktree is not relied on (its work landed in `a0d88d3` as #8).

## Success Criteria

- `govulncheck ./...` reports no reachable findings, on Go 1.26.10, `golang.org/x/text` >= v0.41.0, `golang.org/x/sys` >= v0.44.0; CI runs it on every push and PR.
- `setup` and the image build install Node.js, the playwright-core driver package and Chromium only from files whose sha256 matches a pin in `internal/app/setup/pins.env`; no `playwright.Install` / `playwright install` call remains. A guard test fails when the pins drift from `go.mod`'s playwright-go version or the Dockerfile ARGs.
- Chromium launches with its sandbox on, in Docker (tracked seccomp profile) and natively (AppArmor profile from `setup` where Ubuntu restricts user namespaces). A launch that cannot start the sandbox fails with an error naming the README section; nothing falls back to `--no-sandbox`.
- A symlink inside the working directory that resolves outside it is refused for the MCP script path, `outputDir`, card images and the screenshots folder, before any write; a symlinked archive parent is refused during extraction. In-tree symlinks still work.
- `.screencaster` is 0700 and `jobs.db` (+ `-wal`, `-shm`) 0600; the server and CLI refuse to start when they cannot set this. A job's `script` column is NULL once the job is succeeded or failed (incl. `Recover`); rows stay (BR-007).
- `release.yml` refuses any ref but `refs/heads/main`, runs vet and tests before building, and uploads `SHA256SUMS`. Every `uses:` is a 40-hex SHA with a version comment; every `FROM` of a public image carries `@sha256:`. The runtime image runs as `USER 65532:65532`.

## Scope & Constraints

- **In scope:** H1, H2, M1–M8 as above, their guard tests, and the docs they make stale.
- **Out of scope:** build provenance attestations; Dependabot/Renovate; pinning apt packages (Chromium system deps, ffmpeg); bumping `modernc.org/sqlite` or golangci-lint (stays v2.12.0); arm64 `setup`; dropping the `:latest` push (kept); symlink checks on the CLI's own script argument (a developer may name any script, `plan.go:258-262`, by design); Low findings L1–L4 of the audit.
- **Hard constraints:** NFR-003 (render downloads nothing; only `setup` via `adapters/download`), BR-001 (output bytes unchanged by this work), BR-004 (no partial output), BR-006 (no existing output opened for writing; decision 73 screenshot exception unchanged), BR-007 (rows kept), existing demo YAML unchanged, depguard boundaries kept (a new `os/exec` user is added to the allow list explicitly).
- **Trade-offs:** security over convenience: fail closed on sandbox and on permissions, at the cost of a Docker flag (carried by every shipped launcher) and of projects whose `.screencaster` was left root-owned needing a `chown`. Manual install of the Playwright pieces over `playwright.Install`: more code that tracks Playwright's on-disk layout, in exchange for every byte being pinned.

## Architecture & Design

### High-Level Flow

```
setup (root)                                   image build
  pins.env ──► Fetch(url, .part, sha256) ──►      ARG pins (== pins.env, guard test)
     node tarball ─► ExtractTar  ─► <dir>/playwright-driver/node        curl + sha256sum -c
     playwright-core.tgz ─► ExtractTar ─► <dir>/playwright-driver/package   same layout under /opt
     chromium(.zip) ─► ExtractZip ─► <dir>/ms-playwright/chromium-<rev>/ + markers
     driver `install-deps chromium` (apt, if apt)                       same
     AppArmor userns profile (if restricted)                            n/a (container)
  marker tag = version/pin-sha  → pin change reinstalls

render
  browser.open: Chromium.Launch({ChromiumSandbox: true}) ─ fail ─► error + README#chromium-sandbox
  docker run ... --security-opt seccomp=<tracked profile> --user uid:gid (image USER 65532 default)

paths  within(files, workDir, p): lexical check, then EvalSymlinks(deepest existing) ⊂ EvalSymlinks(workDir)
store  .screencaster 0700, jobs.db* 0600 (refuse on failure); Finish/Recover → script = NULL
CI     Go 1.26.10, govulncheck, actions @sha, images @sha256; release: main only, vet+test, SHA256SUMS
```

### Alternative Approaches Considered

- **H2: verify after `playwright.Install`.** Small, but bytes run as root before the check. Rejected (user).
- **H2: point `playwright.Install` at a local verified mirror** (`PLAYWRIGHT_DOWNLOAD_HOST`, `PLAYWRIGHT_GO_NPM_REGISTRY`, `PLAYWRIGHT_NODEJS_PATH`). Needs a local HTTP server during setup and still depends on driver internals. Rejected.
- **M1: `--cap-add SYS_ADMIN` or a setuid `chrome-sandbox`.** Broader grant / setuid binary in the image. Rejected (user chose a tracked seccomp profile).
- **M1 native: document only.** Native renders on Ubuntu 24.04 would fail out of the box. Rejected (user chose `setup` installs the profile).
- **M2: refuse all symlinks in archives.** Breaks the Piper tarball (relative symlinks, `TestExtract_keepsTopFolderModesAndSymlinks`). Rejected.
- **M3: refuse any symlink.** Breaks repos that link inside the project. Rejected (user).
- **M4: strip cookies before storing.** Breaks queued jobs after a restart. Rejected (user). **Warn on chmod failure:** rejected (user chose fail closed).
- **Pins: `COPY pins.env` into the Dockerfile instead of ARGs.** One source, but a different pattern from Piper; kept as a follow-up.

## Risks & Mitigations

- **Playwright layout drift.** Manual install must match what the driver expects (dirs, markers, headless shell); a mistake breaks every render. Mitigation: step 1 reads the real code first; marker tags force reinstall on pin change; the user-run native and image checks below; CI e2e on the PR exercises the image path.
- **Seccomp profile wrong or stale.** Too strict → sandbox fails (fail closed, every Docker render breaks); too loose → weaker than Docker's default. Mitigation: start from Docker's default at a pinned moby commit and add only the userns pieces; CI e2e (Docker) runs Chromium with it on the PR; wrapper copy byte-guarded.
- **Users with their own `docker run` / `.mcp.json`** lack the flag after upgrade → renders fail closed. Mitigation: error text names the README section; release notes (user action) call it out.
- **AppArmor install as root writes outside the install dir** (`/etc/apparmor.d`). Mitigation: fixed file name and content, fixed `apparmor_parser` argv, only when the sysctl says restricted; documented in ARCHITECTURE §14.
- **Fail-closed chmod breaks projects with root-owned `.screencaster`** (old root container runs). Mitigation: error names the exact `chown`; README note.
- **Symlink resolution false positives** (work dir itself under a symlink, `/work` bind mounts). Mitigation: work dir resolved with `EvalSymlinks` before comparing; in-tree link test.
- **Zip extraction is new code on downloaded input.** Mitigation: sha256 checked before extraction; shared guarded entry writer; zip unsafe-entry tests.
- **`USER 65532` without `--user`** cannot write the mounted `/work` owned by the caller. Mitigation: wrapper, compose and README already pass `--user`; error is a plain permission error.
